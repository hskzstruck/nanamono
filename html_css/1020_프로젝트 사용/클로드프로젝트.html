01 프로젝트란?

프로젝트는 클로드 안에 만드는 전용 작업방이다. 규칙과 참고 자료를 한 번 넣어두면, 그 안에서 시작하는 모든 대화에 자동으로 적용된다. 같은 작업을 반복할 때 매번 처음부터 설명하지 않아도 된다.

프로젝트에 넣는 2가지
  • 지침 클로드가 매번 지켜야 할 규칙. 예: "초심자 눈높이로 설명해줘"
  • 파일(컨텍스트) 이 프로젝트 안에서 사용할 참고자료
    주의: 파일이 많거나 클수록 한도를 더 빨리 쓰니 꼭 필요한 것만 올린다. 지침에 파일 이름과 사용 방법을 적어두면 더 확실하게 참고한다.
프로젝트 메모리

메모리는 대화 내용을 요약해서 기억하는 기능이다. 무료도 기본으로 켜져 있고, 프로젝트마다 따로 만들어진다. 다만 큰 틀의 요약만 저장되어, 세부 수정 내용이나 만든 파일은 새 채팅에서 볼 수 없다.

새 채팅에서 이어서 작업하려면 완성본 파일을 프로젝트 파일이나 첫 메시지에 올리고, 이전 채팅에서 "작업 인계 메모(완료한 것, 정해진 규칙, 남은 할 일)"를 받아 첫 메시지에 붙여넣는다.

⚠️ 꼭 알아둘 2가지
① 프로젝트 이름과 설명은 클로드가 읽지 못한다. 규칙은 반드시 "지침"에 적어야 한다.
② 프로젝트 안의 대화 내용 자체는 서로 공유되지 않는다. 메모리는 요약이라 정확하지 않을 수 있으니, 꼭 지켜야 할 규칙은 메모리가 아니라 지침이나 파일에 넣어야 한다.
02 무료 플랜의 제한 (Claude 기준)
⚠️ 무료 플랜의 제한은 정책에 따라 수시로 바뀌니 꼭 최신 내용을 확인하여야 한다. 여기 적힌 내용은 2026년 10월 기준이다.

무료로도 프로젝트를 쓸 수 있다. 아래 제한만 알고 시작한다.

  • 무료 프로젝트 개수: 최대 5개
  • 사용량: 5시간 단위 (유료도 같은 방식이나 총량이 다름)
  • 한 대화에서 기억하는 양
📌 최신 내용은 support.claude.com에서 확인한다.
03 프로젝트 만들기
1
프로젝트 메뉴 열기
claude.ai에 로그인한 뒤, 사이드의 프로젝트 탭을 클릭한다. 주소창에 claude.ai/projects를 입력해도 된다.
2
새 프로젝트 클릭
(프로젝트 탭 > 오른쪽 위 새 프로젝트) 버튼을 누르면 프로젝트 생성 창이 뜬다.
3
이름과 설명 입력하고 생성
이름 : 내가 알아보기 위한 용도
설명 : 내가 알아보기 위한 용도
컨텍스트 : 필요 파일 첨부 (선택 사항)
(추후 파일 추가: 사이드의 프로젝트 탭 > 프로젝트 이름 클릭 > 컨텍스트)

마지막으로 프로젝트 생성 버튼을 누르면 프로젝트 화면이 열린다. 이 화면 오른쪽에 지침, 컨텍스트, 메모리가 있다.
💡 2026년 10월 현재 한국어 화면 기준이다. 화면 구성은 업데이트에 따라 달라질 수 있다.
04 지침 만드는 법 (채팅으로)

지침은 처음부터 직접 쓰지 않아도 된다. 클로드와 채팅하면서 만들면 된다. 생각나는 규칙을 대충 던져주면 클로드가 지침 문장으로 정리해준다.

먼저 생각해볼 것들
  • 나는 누구인가 어떤 상황에서 쓰는지 (예: 웹퍼블리싱을 배우는 초심자)
  • 어떤 눈높이로 설명받고 싶은지 (예: 처음 배우는 사람 기준)
  • 어떤 형식으로 답을 받고 싶은지 (예: 코드는 HTML, CSS, JS로 나눠서)
  • 지켜야 할 규칙 (예: 추정하지 말고, 필요한 사항이나 파일이 있으면 요청하기)
  • 하지 말아야 할 것 (예: 모르면 아는 척하지 않기)
1
새로 생성하고 생각나는 규칙을 두서없이 보내기
사이드의 새로 생성을 클릭해 일반 채팅에서 시작한다. 정리가 안 돼 있어도 괜찮다. 아래처럼 보내면 된다.
나 웹퍼블리싱 배우는 중인데 이 프로젝트에서 계속 작업할 거라서 Claude 프로젝트 지침 만들고 싶어 시안 올리면 html css js 나눠서 코딩해줬으면 좋겠고 결과는 코드블럭으로 html은 기본구조 필요없고 모르면 추정하지 말고 필요한 거나 파일 있으면 먼저 물어봐 지침은 짧게 규칙별로 한 줄씩 정리해줘
꼭 들어가야 할 말
시안 작업의 기준이 무엇인지 알려준다.
html css js 나눠서 한 덩어리가 아니라 파일별로 나눠 받기 위해서이다.
코드블럭 복사해서 붙여넣기 쉬운 형태로 받기 위해서이다.
html 기본구조 필요없음 head, body 같은 뼈대를 빼고 필요한 부분만 받기 위해서이다.
추정하지 말고 먼저 물어봐 없는 내용을 지어내는 것을 막는다.
말투는 달라도 되지만, 위 단어가 빠지면 그 규칙이 지침에서 빠질 수 있다.
2
정리된 지침을 읽고 고치기
"이 부분은 너무 길어", "이 규칙이 빠졌어"처럼 말하면 된다. 애매한 문장은 "이 문장을 더 구체적으로 써줘"라고 요청한다.
3
등록하기 전에 검수하기
붙여넣기 전에 한 번 더 점검한다. 확인할 것은 두 가지이다. ① 클로드가 모르는 걸 지어내게 만드는 문장은 없는지 ② 규칙이 너무 많거나 빡빡해서 오히려 답이 이상해지지 않는지. 일반 채팅에서 아래처럼 요청한다.
모르는 걸 지어내게 만들 수 있는 문장이 있는지, 규칙이 너무 많아서 이상해질 부분이 있는지 보고 검수해줘. 그리고 필요한 내용만 간단하게 지침으로 적어줘.
4
프로젝트 지침란에 붙여넣기
03번에서 만든 프로젝트의 (사이드의 프로젝트 탭 > 프로젝트 이름 클릭 > 지침 > 편집)에 붙여넣고 저장한다. 저장한 뒤 새로 시작하는 대화부터 적용된다. 참고 파일도 (컨텍스트 > 추가)에서 이때 같이 올린다.
5
프로젝트 안에서 진짜 작업으로 테스트
실제로 할 작업을 하나 시켜본다. 결과가 마음에 들지 않으면 어디가 어떻게 마음에 들지 않는지 말해준다.
6
고친 내용을 지침에 반영하기
테스트하면서 고친 내용은 지침에도 반영하여야 한다. 고친 부분만 끼워 넣지 말고, 일반 채팅에서 전체를 다시 적어달라고 요청한다.
방금 내가 지적한 내용까지 반영해서 지침 전체를 다시 적어줘.
받은 지침으로 기존 지침을 전부 지우고 붙여넣은 뒤 저장하면 끝이다. 저장한 뒤 새로 시작하는 대화부터 적용된다.
지침 예시
# 역할 나는 웹퍼블리싱을 배우는 초심자이고, 클론코딩 과제를 이 프로젝트에서 계속 진행한다. # 설명 방식 - 처음 배우는 사람 기준으로, 어려운 용어는 쉬운 말로 풀어서 설명 - 코드는 HTML, CSS, JS로 나눠서 보여주기 # 규칙 - 추정하지 말고, 필요한 사항이나 파일이 있으면 먼저 요청하기 - 확실하지 않은 내용은 확실하지 않다고 말하기
